## 三、刷机步骤

> ⚠️ **重要**：本镜像为 raw dd 格式，**不能用 USB Burning Tool 直接烧录**
> （USB Burning Tool 只认 aml 升级包格式）。请按下面方式 A / 方式 B 操作。
> 刷机会**清空整块 eMMC**，原有系统和数据全部丢失，请先备份。

### 方式 A（推荐）：在已运行 Armbian 的 N1 上刷入

**步骤 1：下载并校验镜像**（在 N1 上执行）

```bash
# 下载镜像与校验文件（地址以发布页为准）
wget https://gitee.com/jinhuwh/jinhu-order-system/releases/.../n1-jinhu-firmware-slim-20260929.img.zst
wget https://gitee.com/jinhuwh/jinhu-order-system/releases/.../n1-jinhu-firmware-slim-20260929.img.zst.sha256

# 校验（必须输出 OK）
sha256sum -c n1-jinhu-firmware-slim-20260929.img.zst.sha256
```

**步骤 2：解压**（需约 7 GB 剩余空间；U盘系统可解压回电脑再传，eMMC 系统建议插一个U盘存放）

```bash
zstd -d n1-jinhu-firmware-slim-20260929.img.zst
# 解压得到 n1-jinhu-firmware-slim-20260929.img（7 GiB）
```

**步骤 3：写入 eMMC**（⚠️ 此步之后原系统即被覆盖）

```bash
# N1 的 eMMC 设备为 /dev/mmcblk2
dd if=n1-jinhu-firmware-slim-20260929.img of=/dev/mmcblk2 bs=4M status=progress conv=fsync
sync
```

约 3-6 分钟（取决于机型读写速度）。写完拔掉U盘（如在U盘系统），重启：

```bash
reboot
```

**步骤 4：首次开机自动初始化**（约 1-2 分钟，详见第五节）

**步骤 5：获取初始凭据**（详见第五节）

### 方式 B：全新 N1（安卓系统）或已变砖

1. 先用 **USB Burning Tool 线刷任意 Armbian ophub 版**（社区通用教程，关键词「N1 刷 Armbian」）把 N1 救到能启动 Linux
2. 再按 **方式 A** 刷入本固件

> 💡 提示：ophub Armbian 刷机流程中已包含「降级 bootloader」等步骤，完成后 eMMC 上即是 Armbian，可直接执行方式 A 的步骤 1。

## 四、首次开机：自动初始化 + 自动扩容

刷机完成后的第一次开机，固件会自动执行初始化脚本（`/root/n1-firstboot.sh`，约 1-2 分钟），共 8 步：

| 步骤 | 动作 |
|---|---|
| 1 | **根分区自动扩容**：把 7GiB 布局扩展到整块 eMMC（8G/16G/32G/128G 自适应），文件系统在线扩容 |
| 2 | 重置设备身份（machine-id + SSH host key 重新生成） |
| 3 | 随机化系统 root 密码 |
| 4 | 随机化开单系统 admin 密码 |
| 5 | 随机化 MySQL root 密码 |
| 6 | 随机化宝塔面板端口、安全入口、密码 |
| 7 | 清理日志与操作痕迹 |
| 8 | 重建 2GB 交换分区，自我禁用 |

**凭据获取**：初始化完成后，在 N1 本机（HDMI + 键盘）登录 `root`（密码见下），执行：

```bash
cat /root/首次启动报告.txt
```

> 📌 **重要**：随机化的密码**只在 `/root/首次启动报告.txt` 中出现一次**，
> 请立即记录并妥善保存，登录后**第一时间修改所有密码**。
> 若 root 无法登录，可在 N1 本机通过单用户模式重置，或重新刷机。

## 六、常见问题

### Q1：我的 N1 是 8G 存储的，能刷吗？
✅ **能**。镜像布局 7 GiB，为 8G eMMC（实际可用约 7.2-7.3 GiB）预留了安全余量。刷完首次开机会自动扩容，把剩余空间全部利用起来。

### Q2：16G/32G 的 N1 刷完是不是浪费了空间？
不会。首次开机的自动扩容会把根分区扩展到整块 eMMC，无论 16G 还是 128G 都能吃满。

### Q3：能用 USB Burning Tool 直接烧这个镜像吗？
❌ 不能。USB Burning Tool 只认 aml 升级包格式，本镜像是 raw dd 格式。全新机器请按「方式 B」先用 Burning Tool 线刷 Armbian，再按「方式 A」刷本固件。

### Q4：刷机后无法开机 / 卡在开机画面
- 多数是原机 u-boot 被覆盖或分区错位：用 USB Burning Tool 线刷 Armbian ophub 包救回，再重刷本固件
- 检查电源适配器是否达标（N1 需 12V/2A）
- 8G 机型请确认下载的是 **slim 瘦身版**，不是 116G 的完整归档版

### Q5：开机后访问 88 端口打不开
- 确认 N1 已连上网络（`ping` 网关）
- 检查服务状态：`systemctl status nginx php-fpm-82`、`ps aux | grep mysqld`
- 查看 Nginx 错误日志：`tail -50 /www/wwwlogs/*.error.log`
- 首次开机的 1-2 分钟内初始化尚未完成，稍等再试

### Q6：忘记 `/root/首次启动报告.txt` 里的密码
- **MySQL root**：宝塔面板 → 数据库 → root 密码 修改
- **开单系统 admin**：宝塔 phpMyAdmin 进数据库改 `users` 表
- **宝塔面板密码**：N1 本机执行 `bt 5` 重置
- **root 密码**：N1 本机单用户模式重置

### Q7：想清空所有数据重新开始（恢复出厂）
```bash
rm -f /var/lib/jinhu-firstboot.done
reboot
```
初始化会重新执行一遍（含随机化所有密码 + 自动扩容）。

### Q8：SSH 连接提示 host key 变更警告
正常现象（每台设备首次开机生成独立密钥），本地清除旧指纹即可：
```bash
ssh-keygen -R <N1的IP>
```

### Q9：需要 PHP 8.1 怎么办
瘦身版镜像只带站点在用的 PHP 8.2。如需 8.1：宝塔面板 → 软件商店 → PHP 8.1 → 安装，约 2 分钟（N1 需联网，编译稍慢）。

### Q10：打开 phpMyAdmin 报 `Function utf8_encode() is deprecated`（数据库页打不开）
镜像内置的 phpMyAdmin 5.1.1 与 PHP 8.2 不兼容导致的，**只影响 phpMyAdmin 这个可选的数据库网页工具**，开单系统与命令行 `mysql` 完全不受影响。修复任选其一：
- 宝塔面板 → 软件商店 → phpMyAdmin → 升级到 5.2.x（推荐，面板会保留数据库列表与入口）；
- SSH 执行一行修复（保留原配置与随机入口目录）：

```bash
cd /tmp && wget -q https://files.phpmyadmin.net/phpMyAdmin/5.2.1/phpMyAdmin-5.2.1-all-languages.zip && unzip -q phpMyAdmin-5.2.1-all-languages.zip && E=$(ls -d /www/server/phpmyadmin/phpmyadmin_*/) && cp ${E}config.inc.php /tmp/pma.cfg && rm -rf "${E:?}"* && cp -a phpMyAdmin-5.2.1-all-languages/. $E && cp /tmp/pma.cfg ${E}config.inc.php && mkdir -p $E/tmp && chown www:www $E/tmp && systemctl reload php-fpm-82
```

执行后刷新 phpMyAdmin 页面重新登录即可。

## 七、安全建议（首次登录后立即执行）

1. **修改 root 密码**：`passwd`
2. **修改宝塔密码**：面板 → 设置 → 修改密码
3. **修改开单系统 admin 密码**：系统内 → 个人设置
4. **修改 MySQL root 密码**：宝塔面板 → 数据库 → root 密码
5. **配置防火墙**：仅放行 88（业务）+ 宝塔端口，SSH 建议改非标端口或限制来源 IP
6. **开启 HTTPS**：为开单系统配置 SSL 证书
7. **定期备份**：数据库 + 站点文件
